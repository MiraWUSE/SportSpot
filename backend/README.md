# SportSpot — серверная часть

В этом разделе находятся база данных, серверная модерация спортивных площадок и интеграция с OpenStreetMap через Overpass API.

Инструкция для **нового пустого проекта Supabase**. Для уже развёрнутого проекта SportSpot повторно выполнять SQL не требуется.

## 1. Какие файлы нужны

```text
SportSpot/
└── backend/
    ├── README.md                              # эта инструкция
    ├── setup.sql                              # создание основной базы данных
    ├── postman/
    │   └── SportSpot.postman_collection.json  # коллекция API-тестов
    ├── sql/
    │   └── 10_overpass_integration.sql        # кеширование и лимиты поиска
    └── supabase/
        ├── config.toml                        # настройки Edge Functions
        └── functions/
            ├── moderate-spot-proposal-v1/
            │   └── index.ts                   # модерация площадок
            └── search-sports-spots-v1/
                └── index.ts                   # поиск площадок через Overpass.ch
```

- **`setup.sql`** — создаёт 8 основных таблиц, связи между ними, ограничения, правила доступа (RLS) и SQL-логику модерации.
- **`sql/10_overpass_integration.sql`** — отдельно создаёт 2 служебные таблицы и SQL-функции для кеширования и Rate Limiting. Для нового проекта запускается **после** `setup.sql`.
- **`supabase/functions/`** — исходный код двух серверных Edge Functions.
- **`config.toml`** — включает проверку JWT для модерации (`true`) и отключает её для публичного поиска (`false`).
- **`postman/`** — проверенные запросы к опубликованному API и автоматические проверки ответов.

## 2. Как установить базу данных

1. Зайдите на [supabase.com](https://supabase.com/dashboard) и создайте **новый проект**. Data API должен быть включён.
2. Откройте проект → **SQL Editor** → **New query**.
3. Откройте файл `backend/setup.sql`, скопируйте весь код в SQL Editor.
4. Нажмите **Run**.
5. Откройте **Table Editor** и проверьте, что появились 8 основных таблиц:

   `profiles`, `spots`, `reviews`, `favorites`, `spot_proposals`, `spot_photos`, `review_photos`, `proposal_photos`.

6. Для работы функции поиска отдельно выполните `backend/sql/10_overpass_integration.sql` через SQL Editor. Он создаст две служебные таблицы в закрытой схеме `app_private`: `spot_search_quota` и `spot_search_cache`.

Структура основной базы и её правила доступа созданы. RLS включён для всех таблиц. Работа с фотографиями через Storage пока не настроена, поэтому их таблицы закрыты для клиентских запросов.

## 3. Как создать пользователя и модератора

1. В Supabase откройте **Authentication → Users**.
2. Нажмите **Add user** и создайте аккаунт со своим Email и паролем.
3. При создании пользователя в `profiles` автоматически появится запись: `name` будет взято из указанного имени или Email, роль — `user`.
4. Если аккаунт должен быть модератором, откройте **SQL Editor** и выполните **от имени администратора проекта**:

```sql
UPDATE public.profiles AS p
SET name = 'SportSpotModerator',
    role = 'moderator'
FROM auth.users AS u
WHERE p.id = u.id
  AND lower(u.email) = lower('EMAIL_МОДЕРАТОРА')
RETURNING p.name, p.role;
```

Вместо `EMAIL_МОДЕРАТОРА` укажите Email созданного аккаунта. В результате должна появиться одна строка с ролью `moderator`.

Обычный пользователь **не может назначить себе роль модератора** через приложение.

## 4. Как установить `index.ts` (модерацию)

**Одного `setup.sql` недостаточно.** Серверную функцию нужно опубликовать отдельно. Самый простой способ — через сайт Supabase.

### Сайт Supabase

1. Откройте свой проект → **Edge Functions**.
2. Создайте новую функцию через встроенный редактор.
3. Назовите её **точно** `moderate-spot-proposal-v1`.
4. Откройте `backend/supabase/functions/moderate-spot-proposal-v1/index.ts` и вставьте весь код в редактор функции.
5. Убедитесь, что **Verify JWT** включён.
6. Нажмите **Deploy**. Функция должна получить статус **ACTIVE**.

Функция доступна по адресу:

```text
https://ВАШ_PROJECT_REF.supabase.co/functions/v1/moderate-spot-proposal-v1
```

`PROJECT_REF` — идентификатор из адреса проекта в Supabase Dashboard. Для вызова модерации необходим JWT пользователя с ролью модератора.

## 5. Как проверить работу

**Проверка базы:** в Table Editor должны отображаться все 8 основных таблиц. Для поиска дополнительно существуют 2 служебные таблицы в `app_private`. В **Authentication → Policies** проверьте, что RLS включён.

**Проверка чтения:** в разделе **API Docs** Supabase можно выполнить GET-запросы к `spots` и `reviews`. В заголовке `apikey` используйте свой `publishable` ключ:

```text
GET /rest/v1/spots?select=*
GET /rest/v1/reviews?select=*
```

Ожидается **200 OK**. Если таблицы пустые, ответ `[]` — это нормально.

**Проверка модерации:** авторизуйтесь под аккаунтом с ролью `moderator` и вызовите Edge Function методом **POST**. Нужны заголовки `apikey` (публичный ключ), `Authorization: Bearer <JWT_МОДЕРАТОРА>` и `Content-Type: application/json`.

Пример тела запроса для одобрения:

```json
{
  "proposal_id": "UUID_СУЩЕСТВУЮЩЕЙ_ЗАЯВКИ",
  "decision": "approved"
}
```

Для отклонения:

```json
{
  "proposal_id": "UUID_СУЩЕСТВУЮЩЕЙ_ЗАЯВКИ",
  "decision": "rejected",
  "reason": "Площадка не подходит"
}
```

Если одобрение успешно, площадка появится в `spots`. При отказе заявка получит статус `rejected` и причину отказа.

**Ожидаемые ответы:** `200` — выполнено; `401` — не авторизован; `403` — нет роли модератора; `404` — заявка не найдена; `409` — заявка уже обработана. Для безопасной проверки доступа можно указать несуществующий UUID и получить `404`, ничего не создавая.

**Формат ошибок:** ошибки, сформированные самой Edge Function, возвращаются в формате {"error":{"code":"...","message":"...","request_id":"..."}}. 
Если JWT отсутствует или отклонён шлюзом Supabase до запуска функции, ответ может иметь другой формат, например {"code":"UNAUTHORIZED_NO_AUTH_HEADER","message":"Missing authorization header"}.
Это ожидаемое поведение.

## 6. Внешняя интеграция с Overpass API

SportSpot использует Overpass API для поиска спортивных площадок из OpenStreetMap.

Запросы к внешнему API выполняются через Supabase Edge Function `search-sports-spots-v1`. По архитектуре мобильное приложение должно обращаться к этой серверной функции, а не напрямую к Overpass.

### 6.1. Установка

1. Создайте проект Supabase и выполните `backend/setup.sql`.
2. В SQL Editor выполните `backend/sql/10_overpass_integration.sql`.
3. Получите API-ключ на https://overpass.ch/.
4. В Supabase откройте Edge Functions → Secrets.
5. Добавьте секрет `OVERPASS_CH_KEY` со значением полученного API-ключа.
6. Создайте Edge Function с названием `search-sports-spots-v1`.
7. Скопируйте код из `backend/supabase/functions/search-sports-spots-v1/index.ts`.
8. Отключите Verify JWT и нажмите Deploy.

Секретный API-ключ нельзя сохранять в исходном коде или GitHub.

### 6.2. Использование API

**Работающий сервер SportSpot (Supabase):**

```text
https://tnqkaamvvxwsimfydurg.supabase.co
```

**Полный GET-запрос для проверки в браузере или Postman (с обязательными координатами):**

```text
https://tnqkaamvvxwsimfydurg.supabase.co/functions/v1/search-sports-spots-v1?lat=56.3269&lon=44.0059&radius=1000&sport=all
```

**Базовый адрес эндпоинта:**

```text
https://tnqkaamvvxwsimfydurg.supabase.co/functions/v1/search-sports-spots-v1
```

**Важно:** открытие только базового адреса эндпоинта без параметров `lat` и `lon` вернёт **HTTP 400** с ошибкой `INVALID_REQUEST`. Это ожидаемая работа валидации, а не неисправность сервера.

Для установки на другом проекте Supabase замените `tnqkaamvvxwsimfydurg` на свой `PROJECT_REF`.

Параметры запроса:

| Параметр | Описание |
|---|---|
| `lat` | Широта от -90 до 90, обязательный |
| `lon` | Долгота от -180 до 180, обязательный |
| `radius` | точный радиус поиска от 100 до 3000 метров, по умолчанию 1000. Передаётся в Overpass без округления. |
| `sport` | `all`, `soccer`, `basketball`, `volleyball`, `tennis`, `fitness`; по умолчанию `all` |

При успешном выполнении сервер возвращает HTTP **200** и JSON с полями `spots` (массив), `count` (количество), `source` (`Overpass API`), `attribution` и `cache` (`hit` или `miss`). Число найденных площадок зависит от координат и актуальных данных OpenStreetMap.

Для кеширования используется ключ версии v2, учитывающий точные координаты, радиус и вид спорта. Это предотвращает получение результатов от другого поискового запроса из-за округления параметров.

Пример ошибки валидации:

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "Invalid coordinates, radius or sport",
    "request_id": "UUID_ЗАПРОСА"
  }
}
```

### 6.3. Надёжность и безопасность

Реализованы следующие механизмы:

- Валидация координат, радиуса и вида спорта.
- Обработка неизвестных и повторяющихся параметров.
- Единый формат ошибок с `code`, `message` и `request_id`.
- Ограничение входящих запросов — 60 в минуту (общий лимит).
- Ограничение обращений к Overpass — 5 в минуту и 500 в сутки.
- Кеширование результатов поиска на 1 час.
- Тайм-аут внешнего запроса — 18 секунд.
- Логирование запросов и ошибок в Supabase.
- Хранение API-ключа в Supabase Secrets.

Основные HTTP-статусы:

| Статус | Описание |
|---|---|
| 200 | Успешный поиск |
| 400 | Некорректные параметры, включая отсутствие обязательных координат |
| 405 | Неподдерживаемый HTTP-метод |
| 429 | Превышение лимита запросов |
| 500 | Ошибка серверной конфигурации |
| 503 | Внешний API временно недоступен |

### 6.4. Тестирование

Коллекция Postman расположена в файле:

`backend/postman/SportSpot.postman_collection.json`

Для проверки:

1. Откройте Postman.
2. Импортируйте JSON-файл коллекции.
3. Выберите коллекцию SportSpot.
4. Запустите Collection Runner.
5. Проверьте результаты тестов.

Коллекция содержит три запроса:

- GET — Search Sports Spots (200).
- GET — Invalid Coordinates (400).
- POST — Method Not Allowed (405).

При проверке успешно пройдены все 10 автоматических тестов. Эта коллекция проверяет функцию поиска; функцию модерации необходимо тестировать отдельно с авторизованным аккаунтом модератора.

Доступность внешнего API зависит от состояния Overpass.ch и действующих лимитов провайдера.
